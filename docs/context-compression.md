2026-10-29：自动会话压缩升级

容量与入口
自动压缩默认开启，开关在“设置 → 模型设置 → 模型”的原压缩模型下方；聊天加号中的手动压缩入口保留。直接使用当前模型原有 contextLength 设置，设置1M就按1M管理，不另设128K或其他聊天容量上限。通常在估算请求量或最近同模型请求用量接近配置容量80%时触发；同时预留回复空间，较大的输出预算可使其更早触发。切换模型后按新模型配置判断。反代实际上限仍须与模型设置匹配。

压缩方法
这是兼容OpenAI兼容/v1、Gemini和Claude常规文本接口的通用方案，不是OpenAI Responses原生encrypted compaction的复制。历史记录按角色、消息ID、完整文字、工具名/参数/结果/状态、附件与来源引用转录。普通消息不再只取前2000字符；附件二进制base64和私有思考不写入文本摘要，保留附件引用。

按保守估算预算分片，超长单条也会拆分，不丢尾部。最多两个压缩请求并发，按时间顺序归并成一份整体目标摘要，明确当前目标、最新要求与更正、硬约束、已完成/未完成、关键证据与文件、失败路径和下一步。单次摘要分片请求的预算会控制在32K以内以提高兼容性，这只是分片大小，不是聊天容量上限。压缩使用设置的压缩模型；未选可用压缩模型时使用当前聊天模型，压缩本身会发生一次或多次模型调用。

保留与回查
较早原消息不删除，只增加压缩检查点。默认保留近期完整用户回合和全部对应工具过程，正在执行/等待批准的工具不会被压到摘要前。在后续模型请求之间检查预算，不在流式文字或工具执行中途挪动消息节点。自动模式使用摘要和近期原文替代按消息条数直接丢历史；关闭自动模式后仍使用原手动与条数设置。

新增内嵌只读read_context_history工具：仅回查当前会话已压缩部分的原消息，可按关键词、消息ID和分页读取完整文本/工具记录，不读取其他会话或任意文件。摘要缺少细节时可继续查原文，而不是凭空补全。

一致性
同会话压缩互斥，提交前检查取消状态与原消息/分支前缀是否仍一致。空结果、未有效缩短、请求失败、不收敛或取消时不创建新检查点。原消息被编辑、删除或切换分支后，受影响的旧摘要标记失效，不再发送给模型；节点顺序、原记录与候选分支保留。翻译、用量、时间和思考显示变化不会误使摘要失效。旧配置和自定义压缩提示保持兼容，仅精确旧默认提示升级为新默认。

验证
167项相关测试通过：37项压缩/预算/失效策略、8项原文回查、20项设置、14项上下文选择、5项消息序列化、74项会话服务与状态回归、9项Android请求集成。Android测试使用独立模拟器和进程内模拟/v1接口，验证压缩前后真实请求JSON、工具回查与模式注入；没有调用用户付费接口。Windows设置持久化测试使用Android SDK 35条件，避免SDK 0下文件替换分支与设备行为不同。优化包构建、签名和非调试标记检查通过。

估算不是服务商精确tokenizer；文本摘要也不是无损记忆，重要细节可以回查保留的原文。原生OpenAI压缩需要服务端支持对应Responses/compact及压缩条目，不能只凭/v1路径认定支持。
